# 腕上银河穿戴主题方案

日期为 2026-11-26，基线为 0.1.33（`aa23284`）。目标是让「智在银河」和「腕上银河」支持场景背景、定时切换和固定单选，并按设备屏形排列车控图标。

0.2.0 试装调整了下面的初版方案。手机入口移到首页「主题」，三端新增海岸灯塔和雪山映湖。长方形手环的单屏和双屏都使用田字格，跑道屏使用单列并跟随手机主题。手机「手环布局」与支持单双屏切换的手环会同步。

## 参考包核对

静态读取「小领通」手机 APK 0.3.30、Watch 5 APK 0.3.20 和 Vela RPK 0.2.7 的清单、资源表和对应字节码。两份 APK 均包含下面 9 张静态 RGB WebP，全部为 960×960，逐张校验字节一致。命名来自资源表，场景对应关系来自 `PhoneLandscape` 和 `WatchFace.Scene`。

| 场景 | 手机日景 | 手表日景 | 共用夜景 |
| --- | --- | --- | --- |
| `SKY` 蓝天与星空 | `phone_day_landscape.webp` | `watch_landscape.webp` | `watch_stars.webp` |
| `RIDGE` 山脊营地 | `phone_day_ridge.webp` | `watch_ridge.webp` | `watch_ridge_night.webp` |
| `CITY` 城市天际线 | `phone_day_city.webp` | `watch_city.webp` | `watch_city_night.webp` |

- 手机与 Watch APK 各自保存场景，可在两端选择。Watch 的 `landscapeSync` 请求与手机回复交换场景、修订值和来源标记。日出日落时间由各端的 `SolarController` / `SolarScene` 处理，支持定位计算、手动时间和 06:00–18:00 本地回退。
- Vela RPK 接收 `appearance=light|dark` 并缓存，随后切换纯色底、文字和图标颜色。资源包包含两组各 8 张 48×48 PNG 控制图标。圆屏和等宽高方屏采用两列，宽高不等的矩形和跑道屏采用单列。单列图标卡有更宽的文字区。
- 原始背景、尺寸、包内资源路径和逐文件 SHA-256 收在本地提取包。维护者确认主题原图已获授权，0.1.34 试装包使用这批素材。车控沿用本项目图标，以明暗卡片配色保障可读性。

## 主题设置

**入口。** 手机在「穿戴设备」卡片提供「外观主题」及效果预览，Watch APK 和 Vela RPK 在设置页提供同名入口。穿戴端默认「跟随手机」，也可以改为「本机设置」。本机设置与最近一次同步的手机设置分别保存，切回跟随时即可恢复手机配置。

| 选择 | 行为 |
| --- | --- |
| 经典 | 使用当前腕上银河配色，首次升级和无可用设置时采用经典 |
| 定时切换 | 选一套场景，每天在它的日景和夜景之间切换。默认 06:00 起显示日景、18:00 起显示夜景，可分别调整两个时间 |
| 固定单选 | 直接选一套场景的「日景」或「夜景」，全天显示这一张。三套场景合计六个选项，设备自动取相应画幅 |

时间按设备本地时区解释，起始时间包含边界。以日景开始为起点计算到夜景开始的循环区间，支持跨午夜。两个时间相同则提示重选，已保存设置可继续使用。打开页面、恢复前台或修改设置时重新计算；页面处于前台时，定时器只等下一个切换点。手环和手表都能用已保存的设置离线切换。

## 屏形和图标布局

| 屏形 | 首页与车控 | 验收尺寸 |
| --- | --- | --- |
| 圆形 | 保留车况页与车控页。车控双列，靠近圆弧的状态、分页点和设置入口使用安全区 | 480×480，另验 400×400 圆屏 |
| 方形 | 车控双列，四个按钮按槽位从左到右、从上到下排列 | 400×400 方屏 |
| 长方形 | 车控单列，按钮内图标与文字横排。Vela 可沿用现有单页／双页选项，空间不足时滚动 | 附图 336×396、现有 Pro 机型 336×480 |
| 跑道形 | 车况和车控纵向滚动，车控单列，顶部和底部胶囊区域留空 | 附图 192×490、现有手环 10 的 212×520 |

有明确圆形或胶囊形标记时优先采用设备标记；明确矩形时按宽高区分方屏、长方形，旧固件缺少形状信息时用已知尺寸和宽高比回退。这样能修正目前 `resolveLayoutProfile()` 把明确标为 `rect` 的 400×400 屏按尺寸识别成圆屏的问题。Android 用 `Configuration.isScreenRound()` 配合窗口可用尺寸；Vela 用 `device.getInfo()`。 [Vela 设备信息](https://iot.mi.com/vela/quickapp/zh/features/basic/device.html) · [Android 手表屏形适配](https://developer.android.com/training/wearables/views/layouts)

车控卡采用清晰的图标＋短标签，按官方组件实际槽位布局。一项或奇数项用现有空位处理策略适配。给浅底和深底分别准备易读的图标配色，按钮的可用、加载和禁用状态同时通过文字或图形表达。车图、里程、车控和背景分别渲染，昼夜切换只更新背景与外观配色，确认页面使用有足够对比度的独立面板。

## 实现落点

1. **统一主题定义。** 三端共享主题 ID、日夜变体和默认时间规则。外观配置包含 `themeId`、`mode`、`variant`、`dayStartMinute` 和 `nightStartMinute`，其中 `mode` 使用 `schedule` / `fixed`，`variant` 使用 `day` / `night`。每个端根据主题、时间和屏形决定背景及前景配色。固定单选只读取 `variant`，定时切换读取两个分钟值。
2. **手机保存并同步。** 在 `MainActivity.java` 加预览和编辑入口，在 `GarageApp.java` 持久化配置。复用 Vela `interconnect` 与 Android Watch SPP 的 `hello` / `status` 回复，在 `BandMessage.java` 声明能力 `theme_v1`，状态回复增加可选字段 `theme`。沿用协议 v1、原有请求 ID 和设备授权，读取到完整有效配置后按需应用。测量 2,048 字节上限内的最坏车况回复，超过时让车况、控制状态和确认数据优先；若常态载荷无法容纳主题配置，则在实现时通过能力协商改为独立的主题查询。
3. **Android Watch 先落地。** 在 `WatchActivity.java` 的设置、首页和车控页接入主题，在 `WatchProtocol.java` 验证和解析配置，利用 `SharedPreferences` 保存在用配置和手机同步配置。用现有两页结构和车图缓存；优先以 WebP 按实际可用尺寸解码。切换主题时更新已存在的视图，正在确认的操作仍由原确认状态校验。
4. **Vela 手环与手表。** 扩展 `band/src/common/layout.js` 的布局类型和 `band/src/pages/garage/index.ux` 的背景、卡片、文字与图标样式，使用 `@system.storage` 保存主题。Vela 首版用内置 JPG 背景和 PNG 图标，根据实际屏幕准备方形／圆形共用、长方形和跑道屏三种画幅。单页滚动以屏幕为背景裁切参考，主题层按实际屏幕分辨率预算解码内存。背景读取失败时即时回到经典配色。 [Vela 图片格式及缩放](https://iot.mi.com/vela/quickapp/zh/components/basic/image.html) · [Vela 数据存储](https://iot.mi.com/vela/quickapp/zh/features/data/storage.html)

## 验收

- 定时模式覆盖 05:59／06:00、17:59／18:00、跨午夜、自定义时间、失效设置、重启和时区变化。固定单选跨越两个边界仍持续展示选中背景。
- 各屏形验证两套日夜配色和四个槽位，重点看圆弧安全区、长标签、跑道屏最底部按钮、设置入口及确认页的可读性。用圆形和方形的同尺寸用例检验识别结果。
- 比较新旧手机和新旧穿戴端，检查主题缺失、未知 ID、超长消息和离线重连。跟随手机模式应用有效配置，本机设置模式应用本地配置。
- 回归银河、吉利汽车和领克的车图与里程、槽位排序、加载时保留按钮、确认和取消。检查不同主题下的图标点击区域、表冠分页和手环滚动，实机记录 RPK 体积、主题切换耗时和内存表现。

0.1.34 已实现三端主题、同步与屏形布局，并完成构建、两套 Vela 回归及 Android 单测和 lint。真机适配待试装验证。
